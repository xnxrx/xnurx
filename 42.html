27 — Mis-delivery izin: prompt menyebut X, entri setelan mendarat di mana?

URL nyata halaman ini… Origin nyata (top)… AlurFrame meminta izin Notifikasi (jinak — berkas ini tidak pernah membuat notifikasi). 350 ms kemudian origin frame itu diubah menjadi data: (opaque) selagi prompt masih terbuka. Lalu kamu menjawab prompt. Yang dibandingkan(1) teks prompt · (2) origin frame saat kamu menjawab · (3) entri di setelan izin per-situs 
(belum dijalankan)

Setelah menjawab, buka daftar pembukuan browser dan bandingkan:
Chrome/Edge/Opera: chrome://settings/content/notifications — Firefox: about:preferences#privacy → Izin → Notifikasi → Setelan — Safari: Pengaturan → Situs Web → Notifikasi.

VULNERABLE bila: entri yang tercatat di setelan bukan origin yang disebut prompt — mis. tercatat untuk origin frame yang baru (opaque/data:), untuk origin lain, atau izin tersimpan padahal frame sudah bernavigasi sebelum kamu menjawab. Kapabilitas persisten mendarat di origin yang salah.

SECURE bila: prompt dibatalkan saat frame bernavigasi, atau entri setelan tercatat tepat untuk … — sama persis dengan yang disebut prompt.

Baseline aman (lengan kontrol): tombol kedua meminta izin dari dokumen top-level tanpa frame dan tanpa pertukaran origin. Entri setelan wajib sama persis dengan origin di panel atas. Kalau kontrol pun meleset, temuannya bukan pertukaran origin melainkan pembukuan izin itu sendiri.

Cara mencabut: pada halaman setelan di atas, hapus entri untuk origin ini (Chrome: ikon tempat sampah; Firefox: “Hapus Situs Web”). Prompt akan bisa muncul lagi setelahnya.
