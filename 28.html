PAGAR
Address bar boleh melukis URL tujuan selagi navigasi masih pending. Mitigasinya bukan "jangan dilukis", melainkan asumsi waktu: setiap navigasi diperkirakan segera commit atau segera gagal, sehingga bar melukis ulang dan jendela desync ≈ 0 ms. Di Chromium keluarga masalahnya dikenal sebagai pending navigation entry URL spoof (pending entry dibuang untuk navigasi renderer-initiated / saat ada interaksi user). [nomor bug spesifik sengaja TIDAK dikutip di sini — UNVERIFIED; jangan tulis angka yang belum kamu cek sendiri di issue tracker]
CELAH
Pagarnya berbentuk asumsi, bukan pengecekan. Yang menentukan lama pending adalah tujuan (host+port), bukan browser. Port yang paketnya di-drop diam (tanpa RST/ICMP) tidak pernah commit dan tidak pernah gagal-cepat → jendela = timeout TCP, bukan ~0 ms. Data lapangan yang memicu berkas ini: google.com:81 COMMIT (bar melukis ulang = aman), google.com:4444 menggantung >13 detik. Kalau jendelanya ditentukan port, ia bisa dipetakan — itulah isi tabel di bawah. Catatan: :7 dan :9 ada di daftar bad ports spesifikasi Fetch → ditolak lebih awal; keduanya berfungsi sebagai kontrol kedua (gagal-cepat = pagar bekerja lewat jalur lain).
UJI
Satu popup aktif pada satu waktu; tiap probe ditutup otomatis saat commit atau saat mencapai cap.

ORACLE
BYPASS (jendela ada): kolom verdict berisi HANG(cap) — dokumen popup masih same-origin dan bisa dibaca/ditulis opener selama ms itu, padahal address bar melukis https://www.google.com:PORT/.
PAGAR MASIH BERLAKU: verdict COMMIT dengan ms terbatas dan jauh di bawah cap → bar melukis ulang, jendela habis.
Batas kejujuran: JavaScript tidak bisa membaca address bar. Yang diukur berkas ini adalah syarat perlu-nya (dokumen belum commit). Bukti visual = screenshot address bar saat status menunjukkan HANG. Kalau bar ternyata melukis about:blank, tulis itu apa adanya: pagarnya menang untuk browser tersebut.
KONTROL
Baris 443 (https://www.google.com/) adalah URL yang commit normal. Ia harus berakhir COMMIT dengan angka kecil dan terbatas. Kalau kontrol ikut HANG(cap), yang kamu ukur bukan port melainkan jaringanmu — buang hasilnya.

BATAS / ETIKA
Non-destruktif: hanya GET navigasi biasa ke host publik, satu koneksi pada satu waktu, popup dibatasi satu dan selalu punya tombol tutup, tiap loop punya cap. Tidak ada form, tidak ada input kredensial, tidak ada fetch/XHR/beacon, tidak ada pengiriman data ke mana pun. google.com dipakai murni sebagai label URL yang tak berbahaya.
