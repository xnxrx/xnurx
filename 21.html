38 — OKLUSI: bisakah halaman menutupi wilayah notice fullscreen?

PAGAR Ketika chrome browser disembunyikan atas izin user, permukaan browser-controlled yang tersisa cuma NOTICE fullscreen di atas-tengah (+ jalan keluar Esc). Notice itu seharusnya digambar oleh proses browser dan dikomposit di atas seluruh konten halaman, sehingga elemen halaman dengan z-index setinggi apa pun tidak bisa menutupinya. Mozilla membayar kelas “notice tertutup / tak teramati” (CVE-2021-43538, CVE-2023-37207, MFSA-2024-33 / MFSA-2024-39); Chromium menganggap obfuskasi toast bukan isu keamanan → laporkan ke Mozilla.
CELAH Pagarnya geometris dan per-permukaan: ia mengandalkan notice berada pada layer di atas konten. Kalau di suatu platform/mode (mobile, kiosk, PWA/WebView, jendela non-standar, atau saat notice dirender di dalam konten) urutan komposit itu tidak dijamin, maka menggambar kotak buram di koordinat yang sama sudah cukup — tanpa satu pun API istimewa. Berkas ini tidak menirukan UI browser: kotaknya jelas ber-watermark DEMO dan bertuliskan bahwa ia elemen halaman.

ORACLE
BYPASS: pada arm OKLUSI, teks notice tidak terbaca sama sekali karena tertutup kotak DEMO, sedangkan pada KONTROL notice terbaca jelas → laporkan sebagai bypass-of-fix untuk kelas notice-obscured, sertakan hitungan (mis. “tertutup 18/20”) dan rekaman layar.
PAGAR MASIH BERLAKU: notice tetap terbaca di atas kotak DEMO pada semua run → komposit browser menang; catat “tertutup 0/20” sebagai ilmu-negatif ber-tanggal + versi build.
Perkiraan jujur: pada Firefox/Chrome desktop terkini pagar diperkirakan menang (notice = UI proses-browser). Berkas ini bernilai justru sebagai pengukur lintas-platform: mobile, PWA/WebView, jendela pop-up, dan fork (Arc/Brave/Vivaldi/Opera/Samsung) sering tertinggal di belakang.
KONTROL Arm hijau memasuki fullscreen dengan overlay dimatikan. Kalau di arm KONTROL pun notice tak terlihat, penyebabnya bukan oklusi (mis. notice memang sudah lewat, atau kebijakan build) — dan angka arm UJI menjadi tak bermakna.
